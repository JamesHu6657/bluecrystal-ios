# BlueCrystal iOS

给 mizzzee_0032 用的 iOS 控制 App（SwiftUI + CoreBluetooth）。

## 功能

- **手动控制**：照官方 App 的三个 tab
  - 技能：官方五个预设（如影随形 / 疾风旋舞 / 幻影随行 / 水光环绕 / 神龙摆尾）
  - 变频：伸缩 / 震动 / 吮吸 0~9（0x06 帧）
  - 手动：伸缩 / 震动 / 吮吸 0~99（0x08 帧）
  - 一键停止
- **视频联动**：选本地视频 + 载入时间轴 JSON 脚本，播放时按时间自动发官方 0x08 帧
- 旋转通道不显示、恒发 0：官方面板默认滑杆只有伸缩/震动/吮吸，内置 mizzzee 配置和技能预设都没用到它

## 安全机制（数值照搬 legacy `src/safety/limits.py`）

- 单次连续输出最长 20 分钟（1200 秒），到点自动停止
- 滚动 30 分钟内最多输出 1200 秒；每次停止后冷却 max(60 秒, 本次时长 × 0.5)，冷却/额度不够时拒绝开始，界面显示剩余秒数
- 手动、技能、视频的每一帧都经过同一个准入检查；冷却和额度跨 App 重启保留
- 停止 = 0x08 停止帧 → 100ms → 0x06 停止帧（官方迷姬专用停止 video.js handleSlide 的顺序），两帧都收到写入回执才算停；
  失败整对重发，1→2→4→8→16→30 秒退避一直重试；30 秒仍未确认会锁定输出，需关机后点「已物理关机，解除锁定」
- 断开前必须确认停止；确认不了时可以「强制断开」（会再次警告）
- 界面心跳丢失 5 秒、退后台、App 退出、重新连上时都会发停止帧对

## 协议（参数取自官方 App 醉清风 3.5.1 源码 + 真机实抓）

- Service `FFA0` / Write `FFA1`（Write With Response）/ Notify `FFA2`（真机 GATT）
- 通用帧（官方 `be()`）：`AA <cmd> <len> <payload> <checksum>`，checksum = 前面所有字节和的低 8 位
- 通道顺序（官方 `getSlideProtocolIndex`）：伸缩 0 / 震动 1 / 吮吸 2 / 旋转 3
- 0x06 模式帧（官方 `Tt()`）：`AA 06 05 <4 通道> 00 <cs>`，技能预设 / 变频（0~9）用
- 0x08 帧（官方 `at(arr, t)`）：`AA 08 06 <4 通道 0~99> <t 高> <t 低> <cs>`，手动 tab 和视频联动用，t 恒为 0
- 视频联动强度照官方 video.js（迷姬 devType 2）：`status = 十档值 × 10`（百分制直接用），取整，非零 +10，最高 99，再 `at(…, 0)`
- 停止帧对：`AA08060000000000FFB7`（官方 `at([0,0,0,0],255)`）→ 100ms → `AA06050000000000B5`（官方 `Tt([0,0,0,0])`，真机实抓一致）
- FFA2 通知会订阅并原样显示 HEX（含义未知，只记录）
- 默认技能"如影随形" `AA06050406050000C4` = 真机实抓的官方启动帧

## 出包（GitHub Actions）

push 到 main 后先跑 `Tests/ProtocolChecks`（钉住帧字节、官方换算、安全上限、AI 指令解析和停止词），再编译 unsigned IPA，
在 Actions 页下载 `BlueCrystalIOS-unsigned`。App 里「最后一帧」区块显示版本号和构建提交。
Publish Release 会核对运行结果、构建提交、sha256 和 tag 与版本号是否一致。

## 安装到 iPhone（自签）

unsigned 包不能直接装，需要自签（二选一）：

**AltStore**（推荐，有自动续签）：
1. 电脑装 AltServer，手机装 AltStore
2. 把 IPA 拖进 AltStore 安装

**Sideloadly**（Windows 也行）：
1. 打开 Sideloadly，选 IPA，填 Apple ID
2. 点 Start 安装（免费账号证书 7 天过期，到期重装一次）

## 时间轴脚本格式

```json
{
  "intensityScale": "ten",
  "commands": [
    {"commandType": "Thrust", "startTimeSeconds": 0, "durationSeconds": 5, "intensityLevel": 5},
    {"commandType": "Vibration", "startTimeSeconds": 5, "durationSeconds": 5, "intensityLevel": 7}
  ]
}
```

- `commandType`：Thrust（伸缩）/ Vibration（震动）/ Suction（吮吸）；Rotation（旋转）会被忽略
- `intensityScale`：`"ten"`（0~10，官方格式）或 `"percent"`（0~100）。请务必写上：
  不写时只有出现 >10 的值才能确定是百分制；所有值都 ≤10 时分不清，会按较弱的百分制处理并提示
- 换算成 0x08 强度：十档 5 → 60、10 → 99；百分制 50 → 60（见上面的官方公式）
- 短于 0.1 秒的命令也至少发一次

## 注意

- 连设备前先断开官方 App（蓝牙独占）
- 0x08 帧和 0~99 范围来自官方源码，mizzzee_0032 真机还没抓到过 0x08 帧（视频联动和每次停止都会发它）
- 官方会按设备从服务器下发滑杆范围（slideInfo），0032 的这份配置没拿到，用的是官方默认值
- **停止确认的含义（M4）**：App 说「停止已确认」，只表示停止帧对两帧都拿到了 BLE 写入回执（链路层），不代表设备已经执行；
  主停止帧 `at([0,0,0,0],255)`（`AA08060000000000FFB7`）还没有在 mizzzee_0032 真机上抓到或验证过，代码层面无法证明它能让设备停。
  上身之前必须在设备不接触身体、随手能断电的条件下逐项物理验证：① 手动 0x08 拉到较高强度后点「停止」；② 视频联动中暂停 / 停止；
  ③ AI 程序以 `[STOP]` 结束、以及中途的全零步；④ 输出中退到后台；⑤ 看门狗 / 单次上限自动停机。任何一项设备没真的停下就不要上身，
  并把当时「最后一帧」和 FFA2 通知日志留下来分析

### 1.7.4（build 174）

- 修复点停止后设备不停：0x08 停止帧改为官方迷姬专用停止 `at([0,0,0,0],255)`（`AA08060000000000FFB7`），100ms 后仍发 0x06 停止帧；之前的 `at([0,0,0,0],0)` 只是强度 0。
- 单次连续输出上限调到 20 分钟；滚动 30 分钟额度同步调到 1200 秒，未知时长恢复冷却随之为 600 秒。
- 视频联动新增全屏播放：点画面显示/隐藏控制条，播放、暂停、拖动、停止都走联动逻辑；支持横屏。
- 新增「AI 控制」页：服务商 DeepSeek 官方（deepseek-flash）、Fireworks（deepseek-v4p1-flash）、Command Code GOAT（deepseek-v4.1-flash / claude-haiku-5-5 / muse-spark-1.3-contributor，分别走 chat/completions、messages、responses），每家 Key 分开存钥匙串；默认提示词「明月栞那」可在设置里改；指令 [CH 伸缩 震动 吮吸 0]（0~99，0x08 帧）/ [HOLD 毫秒] / [STOP]，最后强度保持到下一句；说“停/受不了”本地立即停且本轮回复不再执行；全零中途暂停发完整停止帧对（见下）；所有输出仍受单次上限、额度、冷却和看门狗约束。
- AI 控制安全收紧：
  - 停止词随时本地生效，等回复时也能发；中文安全短语（停/停止/别动了/够了/不要了/疼/受不了/慢点停…）出现在消息任意位置、英文独立单词 stop（不分大小写）都会停；“慢”仍交给模型降档。
  - 用户停止、被动停机（看门狗/上限/冷却/输出被拒/退后台）、程序以 [STOP] 或全零自动结束、连接离开“已连接”、离开 AI 页都会作废待执行的回复；执行前在主线程再核对授权代次、连接、安全状态、前台和当前页面，后台期间 BLEManager 也拒绝输出。
  - 指令必须独占一行、不在代码块/引用/句中（代码块按 CommonMark 围栏的字符和长度判断，没闭合算到结尾，围栏样式含糊时有指令就作废）；CH 恰好 4 个非负整数、HOLD 恰好 1 个正整数、STOP 无参数；格式错、行内指令、STOP 后还有指令、超过 40 步时整条回复一步都不执行，正在输出则安全停止。
  - 回复未正常结束（finish_reason≠stop / stop_reason≠end_turn、stop_sequence / status≠completed）只显示文字、不执行，正在输出则停止。
  - 没执行的回复回传显示文字而非指令原文；每次请求带最近 20 条消息。
  - API Key 保存改用 SecItemUpdate/SecItemAdd 并检查结果，只写改过的 Key；失败时已写入的 Key 改回原值、服务商/模型/提示词也不保存，设置页不关、显示错误。钥匙串读取只有“不存在”才当空 Key，其他读取失败的原值记为未知，回滚时跳过、绝不删除。
  - 代码块外的指令行只允许 0~3 个空格缩进（制表符或 4 格以上可能是缩进代码块，整条作废）；出现 `<pre`、`<code`、`<!--` 或围栏字符后紧跟组合符号时，有指令就整条作废；围栏长度按 Unicode 标量数。
  - 回复授权的生命周期抽成纯类型 `ReplyAuthorization`（发送领票、任何停止都作废、执行前验票），ProtocolChecks 覆盖自动停止、用户停止和未停止三种情况。
- 盲审修复（3 高 / 5 中 / 7 低）：
  - 全零输出统一在 `submitOutput` 处理（`OutputGate`）：运行中换成完整停止帧对 at(0,255) → 100ms → Tt(0)，运行不结束、不锁闸，之后的非零帧照常继续；设备没在输出时直接丢掉，不开始运行、不占额度。手动滑杆全拉到 0、视频全零段、AI 全零步都走这里。
  - AI 安全在代码里执行（`AISafety`，不靠提示词）：CH 任一值超过 99 整条回复不执行；每通道上限 70（超过压到 70，程序说明里标出）；每步每通道最多升 20，升得更多时自动插入 1 秒一步的爬升步（降低立即生效）；从空闲开始从 0 爬升。
  - AI 运行中任何请求错误（HTTP、超时、429、断网、钥匙串读取失败）都停止；程序走完保持最后强度时，120 秒没有新的用户消息就停止。手动页 300 秒没有操作自动停止。
  - 非停止帧最多一笔写入在途，在途期间只留最新一帧（`OutputWriteCoalescer`）；停止前丢掉待发输出，停止帧不会排在积压的输出后面。`sendStop` 锁闸，停止后的尾帧/tick 丢弃，只有用户操作能重新开闸。
  - 冷却封顶 600 秒（恢复出来的/未知时长同样封顶），额度仍按推断时长保守记账。
  - Anthropic messages 同时带 `Authorization: Bearer` 和 `x-api-key`；只给标了支持推理的模型（muse-spark）发 `reasoning`；出错提示不进请求历史，历史窗口从用户消息开始；钥匙串读取失败显示真实错误；停止词增加 暂停/等等/疼死 和英文独立单词 pause/wait/enough。
  - FFA2 通知日志带时间戳、距最近一次写入的间隔和待回执数，供真机分析（行为不变）。
- Brain 审查修复（H1、M1–M5、L1–L7；版本号不变）：
  - 在场超时（H1）：AI 运行中不论在执行程序还是保持最后强度，离最近一条用户消息 120 秒就停止（之前只在程序走完后计时，一条 40 × HOLD 60000 的回复能无人值守跑到 1200 秒单次上限）；单条程序（含爬升/等待步）总时长超过 120 秒整条不执行。
  - 出口限升幅（M1/L3）：AI 帧带「每通道最多 +20」交给 BLEManager，写入合并器按实际发出的上一笔 0x08 帧（停止帧对确认后按 0）再夹一次，回执慢、在途合并覆盖掉爬升步时设备也不会一步跳过 20；夹掉的差距不补（偏低方向）。VM 记的起点偏高或帧被丢时同样兜住。
  - 时间限速（M2）：`AISafety` 让任意两次升高至少间隔 1 秒（不够就插等待步，等待期间降低的通道立即生效），跨回复按上次升高的时间算；界面的「每秒每通道最多 +20」和代码一致。
  - 准入决策抽成纯类型（M3）：`OutputAdmission`（链路/后台 → 闸门 → 可能仍在输出 → 停止进行中 → 全零 → 写入/开始运行）、`ManualIdle`（手动 300 秒）、`WriteAckFIFO`、限速合并器、在场超时、程序总时长都进了 ProtocolChecks（含 300 段随机程序的限速性质检查）。
  - 开闸核对被动停机代次（M5）：每次被动停机/断链代次 +1；AI 执行前读到的代次和 BLE 队列上的不一致就不开闸，不再只靠冷却兜底。
  - M4 只更新说明，见「注意」：停止确认是链路层回执，at(0,255) 尚未真机验证，上身前必须物理验证。
  - L1：新一轮停止帧对发出前，回执队列里只剩已超时的停止帧时清空重新对齐，丢失的回执不再让停止永远确认不了。
  - L2：打开 AI 设置前先停止并作废待执行的回复（设置页会盖住停止键）。
  - L4：接口错误只显示状态码和 error.message，遮掉 Key、疑似 Key 片段和长串标识，非 JSON 正文不显示。
  - L5：单次请求总时长上限 45 秒（URLRequest 的 timeoutInterval 只是空闲超时），到点按请求错误处理，运行中则停止。
  - L6：没执行且没有文字的回复以「…」回传，不把「未执行：…」这类本地说明当成模型发言。
  - L7：修正 ProtocolChecks 里 0x08 停止帧的注释（at(…,255)）。
