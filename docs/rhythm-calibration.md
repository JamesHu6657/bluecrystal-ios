# 伸缩频率标定与验证（rhythm-follow P0）

「视频联动 → 画面 → 伸缩跟随动作频率」要把画面里的动作频率（每秒往复几次）换成设备档位。
0x08 帧只能发档位（`[伸缩, 震动, 0, 0]` + 尾字节 0），App 不知道某个档位下设备实际每秒往复几次，所以要在真机上量一次，
把结果填进 App 的「设备标定表」。没标定时 App 用保守猜测（10 档 ≈ 0.5 次/秒、99 档 ≈ 3 次/秒），界面会提示「档位是估计值」。

需要准备：手机 + 设备（mizzzee_0032）、能拍 240 fps 慢动作的手机（可以是另一台）、秒表或慢动作回放里的时间轴、本文末尾的记录表。

## 1. 先确认「伸缩」档位是什么

在 App「手动」页只拉伸缩滑块（震动保持 0）：

| 档位 | 看什么 |
| --- | --- |
| 10 / 50 / 99 | 每秒往复次数是否明显变多（= **速度档**），还是行程变长、次数不变（= **幅度档**），或两者都变 |

- **速度档**（预期）：继续第 2 步，P1 的做法成立。
- **幅度档**：P1 的「频率跟随」不成立（档位改的是行程不是快慢），**不要填标定表**，把结果反馈回来，改走「用强度脉动近似节奏」的路线（P2）。
- **两者都变**：照常标定，记录表里把行程也记下来。

## 2. 每档的往复频率

1. 手动页：伸缩依次固定在 **10、20、30、40、50、60、70、80、90、99** 档，每档保持 **10 秒**（换档后先等 2 秒稳定再计时）。
2. 用 240 fps 慢动作对准可见的往复部件拍摄；回放时数 **整 5 秒内完成的完整往复次数**（一进一出算 1 次），除以 5 得到「次/秒」。
   - 次数少的低档可以数整 10 秒；数不清就数两遍取平均。
   - 也可以贴一小块胶带当标记，逐帧看它回到同一位置的帧号：频率 = 240 ÷ 一个周期的帧数。
3. 记下设备开始动的最低档（死区）：低于它的档位不要写进表里。
4. 记下每档时「设备通知（FFA2）」（手动页 → 设备详情）有没有规律变化。含义未知，只记录；如果和往复位置同步变化，后续 P2 有可能拿它做相位反馈。

## 3. 响应时间（选做，但建议做）

1. 手动页把伸缩从 **20 → 80** 档，慢动作里数「松手（档位变）到频率明显变快」用了多少帧；再 **80 → 20** 测一次。
2. 按 STOP，记下设备停在行程的哪个位置（每次都一样 / 随机）。
3. 视频联动模式下 App 每 0.3 秒最多升 20 档（下降不限速），所以 20 → 80 档至少要 0.9 秒；如果设备自己的加速比这慢很多，体感延迟主要来自设备。

## 4. 把结果填进 App

「视频联动」页 → 来源选「画面」→ 打开「伸缩跟随动作频率」→「设备标定表」里填：

```
档位:每秒次数, 档位:每秒次数, ...
例：20:0.6, 40:1.1, 60:1.7, 80:2.3, 99:2.8
```

规则（填错时输入框下面会变成警告色，并继续用估计值）：

- 填完按键盘上的「完成」（或点别处收起键盘）才生效；打字过程中设备还按原来的表（或估计值）走，提示里会写「按「完成」或收起键盘后生效」。
- 2~12 组；档位 1~99、次数 0.1~8；按档位排序后**档位和次数都要严格递增**（不递增说明这几档测不准或已经到了设备极限，删掉重复的那几档）。
- 逗号 / 分号 / 顿号 / 空格 / 换行分隔都可以，中文冒号逗号分号也可以，冒号两边可以有空格（例：`20:0.6 40:1.1`、`20：0.6、40：1.1`）。
- App 在两点之间线性插值；画面比表里最快的一点还快就用最高那一档（状态行会提示「比设备最快的 x.x 次/秒还快」），比最慢的一点还慢就用最低那一档。
- 「上限」和「最低强度」照样生效：节奏档位会被抬到最低强度、压到上限（状态行会提示「已到上限」，和「比设备最快」可以同时出现）。状态行里的档位是这一拍实际发出的档位。
- 节奏只在画面确实在动时起作用：画面强度很低时伸缩按比例交回动作强度（强度 25 以上才全按节奏），弱动作（点头、比划手势）有节奏也最多比按强度高一点：按动作本身的强度（不受「上限」影响）算一个上界，强度 10 → 最多 22 档、15 → 30 档、20 → 40 档，20~30 之间逐渐放开，**强度 30 以上的真动作没有这个上界**，不管上限设多少都跟频率（只受上限本身限制）；上界压低了伸缩时状态行会提示「动作偏弱」；画面强度落到门下（动作停了）那一拍起、或切镜后 0.5 秒内回到按强度（只有一拍没分析到画面 / 门一拍没开时伸缩当拍按强度，下一拍回到节奏，不会丢掉已锁定的节奏），不会「画面不动了设备还按旧节奏走」。「动作停了」本身要等画面强度落下来（约 1 秒的窗口），这段滞后开不开节奏都一样。

## 5. 用测试视频验证

```
bash Tools/make-rhythm-test-videos.sh       # 需要 ffmpeg，约 30 秒，生成到 ./rhythm-test-videos
```

| 文件 | 内容 | 预期（状态行「动作节奏 x.x 次/秒」） |
| --- | --- | --- |
| const-0.5hz / 1hz / 2hz / 3hz | 常频 30 秒 | 3~6 秒内稳定在 0.5 / 1.0 / 2.0 / 3.0（±10%） |
| step-1to2hz | 前 20 秒 1 Hz，后 20 秒 2 Hz | 20 秒后 2~4 秒内跳到 2.0（分析窗口 4 秒，要过半才认） |
| sweep-0.5to3hz | 60 秒内 0.5 → 3 Hz | 大致跟上，比实际慢 1~3 秒 |

方块到最右端时音轨会「嗒」一声，可以拿来对照设备的往复时机（P1 只跟快慢，不保证对齐时机）。
在本地用同一套分析代码离线跑过这 6 个视频（缩到 64×36、15 fps）：常频 4 个都锁到 ±1%，阶跃 4 秒内跟上，扫频跟上但有 1 次短暂跳到三分之一频率。
（这是 r1 复审修正之前的结果；之后减半规则改成「最多一次」、跳变确认改成「连续 2 拍同方向」，需要重跑一遍确认。）

验证时同时看设备：标定准的话，设备每秒往复次数应和视频的次数接近（±15%）。差得多就回到第 2 步重测那一段。

注意：测试视频的振幅按「分析帧里每帧最多移动约 5 像素」设计。真实视频里**又快又大**的动作（2 Hz 时单程超过画面宽度约 20%）超过块匹配的搜索范围（8 像素 / 帧），频率可能估成一半，这是画面分析本身的限制。

## 7. 结果怎么用

- 速度档 + 次数随档位单调增加：填表，开「伸缩跟随动作频率」日常使用。
- 设备最快只有 ~1.5 次/秒：视频里更快的动作都会顶到最高档，体感是「跟不上」，属于设备上限。
- 响应时间 > 1 秒：快慢变化会明显滞后；后续 P4（提前读视频）可以补偿一部分。
- FFA2 通知和往复位置同步：反馈回来，P2 相位对齐可以考虑用它做闭环（手动页设备详情里的「FFA2 观察」会自动找周期 / 计数器字节，见第 8.1 节）。

## 8. 相位脉动（rhythm-phase P2）的标定与验证

「伸缩跟随动作频率」打开后的「相位脉动（实验）」：画面往里时伸缩加强、往外时减弱。App 拿不到设备的位置，只能**按画面预测、提前发**，
所以两个参数要在真机上对一次：**延迟补偿**（画面到设备真正变强的总延迟，默认 200 ms）和**方向**（哪边算「往里」）。先做完上面第 1~4 步（标定表必须填好，没标定时不脉动）。

### 8.1 先看 FFA2 有没有位置信息（2 分钟）

1. 手动页 → 设备详情，伸缩固定 50 档跑 10 秒以上，看「FFA2 观察」那一行（最近 20 秒的通知：条数、会变的字节、周期、计数器）。
2. 换 20 档、80 档各看一次。
3. 结果：
   - 「第 N 个按约 x.xx 次/秒周期变化」且 x.xx ≈ 设备实际往复次数（随档位变）→ FFA2 很可能带位置 / 行程，**反馈回来**（可以做闭环，延迟补偿就能自动校准）；
   - 「像计数器（约每秒 +y）」且 y ≈ 往复次数 → 可能是行程计数，同样反馈；
   - 「内容一直不变」/「没有周期变化」/ 条数很少 → 只能开环，继续 8.2。

### 8.2 对延迟补偿和方向

1. 视频联动 → 画面 → 打开「伸缩跟随动作频率」和「相位脉动（实验）」，深度 20、延迟补偿 200 ms、方向不反转。
2. 播放 `const-1hz`（方块左右往复，**到最右端时「嗒」一声**，这一刻就是 App 约定的 θ = 0「最深点」；往右走 = 「往里」）。
   等状态行出现「相位脉动：已对上」。
3. 用 240 fps 慢动作**同时拍到屏幕和设备**（或开着声音拍，用「嗒」声对时），连续拍 10 秒。
4. 回放时记每个周期里：「嗒」那一帧，和设备伸缩最用力（最快）的那一帧。App 让设备在「嗒」之前约 1/8 周期（1 Hz 时 125 ms）最强。
   - 设备最强的时刻**总比预期晚** Δ 毫秒 → 延迟补偿 **加** Δ；**总比预期早** → **减** Δ（滑杆步长 20 ms，0~600）。
   - 设备最强的时刻在「嗒」之后约半个周期（方块往左走时最强）→ 打开「方向反转」，再从第 3 步重来。
5. 换 `const-0.5hz`、`const-2hz` 各看一次：同一个延迟补偿下三个频率都对得上最好；差很多就把三个频率各自的最佳值记下来反馈（说明设备响应和频率有关）。

### 8.3 预期和限制

- 1 Hz 左右最明显；2 Hz 以上脉动自动减弱，**2.5 次/秒以上不脉动**（状态行提示只跟频率）。体感能分清强弱的大概在 1~1.5 次/秒以下（App 每 0.1 秒一档、升幅每 0.3 秒最多 +20，2 Hz 一个周期只有 5 个点、峰谷差最多约 23 档）。
- 峰谷差（深度）默认 20 档、可调 0~40；升幅限速会自动压小：1 Hz 最多约 46、1.5 Hz 约 31、2 Hz 约 23。顶到「上限」时只往下脉动；谷不低于「最低强度」和 8 档。
- 没对上 / 切镜 / 动作停了 / 点头比划手势（动作偏弱）/「仅震动」：不脉动，伸缩和只开「伸缩跟随动作频率」时完全一样。
- 真实视频里人的动作不像测试视频那么规整：状态行里的「拟合 0.xx」越接近 1 越可信；经常在「已对上」和「还没对上」之间跳，说明画面的往复不够干净，属于正常退回。

## 9. 动作识别 / 撞击声相位校正（rhythm-context P3）的验证

P3 的两个开关都**默认关**，不需要新的标定数值；但要在真机上确认它们认得对、不添乱。先做完第 8 节（标定表、延迟补偿、方向）。

### 9.1 开关关着时什么都不变（1 分钟）

1. 「动作识别（实验）」「撞击声相位校正（实验）」都关：仪表区没有「动作识别：」「撞击声校正：」两行；`const-1hz` 上和只开 P2 时体感一样。
2. 只开「撞击声相位校正」但「相位脉动」关着：开关本身看不到，也不起作用。

### 9.2 动作识别

1. 打开「伸缩跟随动作频率」→「动作识别（实验）」。先播 `const-1hz`：状态行应为「动作识别：还没认出动作（按整幅画面跟）」，多半带「用周期区域内的运动」（方块就是周期区域）；频率跟随照常锁上。
2. 换真实视频，插入 / 口 / 手三类各 2~3 段（固定机位、有晃镜头的各一段），每段看 20 秒，记：
   - 状态行认成什么、多久认出（应 ≤ 2 秒）、会不会来回跳；
   - 「往里方向已判断」时：设备强的那半拍是不是画面「往里」；不对就记下来，并试「方向反转」能否救回；
   - 和关着「动作识别」时比，频率跟随（P1 状态行的次/秒）是不是更贴近画面里真正在动的部位。
3. 两个人都在动、或手在画面边上比划的片段：看是否跟对了主动的那个部位（跟错就记时间点反馈）。
4. 连续播 10 分钟：手机温度 / 耗电和不开比；发热时 App 会自动不认姿态（手 / 脸 / 身体上下文都停），状态行回「还没认出动作」属正常。

### 9.3 撞击声相位校正

1. 打开「相位脉动（实验）」→「撞击声相位校正（实验）」，**手机音量打开、视频不静音**（另外试一次手机静音 / 音量 0 时还能不能对齐，记下来）。
2. 播 `const-1hz`（最右端有「嗒」声）：4~6 秒内状态行应变为「撞击声校正：声音 1.00 次/秒和画面一致，已对齐（集中度 0.9x，偏移 +x°）」。
   偏移应接近 0（第 8 节的延迟补偿和方向已经对好时）；偏移稳定在某个大角度（如 ±150°）→ 说明方向或 tap 时间有偏差，记下来反馈。
3. 拖进度条 / 暂停：偏移立刻回 0，重新播放后再收敛。
4. 有配乐 / 说话、没有拍打声的视频：应一直是「没听到和画面一致的撞击声，只按画面相位」，偏移 0。有拍打声的真实视频：看能否「已对齐」、对齐后强弱是不是更贴画面。

## 10. 前瞻 / 预扫描（rhythm-lookahead P4）的验证

P4 的两个开关都**默认关**。前瞻要先做完第 4 节（标定表）才会生效，没标定时打开也和不开一样；预扫描不需要标定。完整清单见 `docs/visual-sync-design.md`「rhythm-lookahead P4」。

### 10.1 开关关着时什么都不变（1 分钟）

1. 「前瞻（实验）」「预扫描整段视频（实验）」都关：仪表区没有「前瞻：」「预扫描：」两行；`const-1hz` 上和只开 P2 / P3 时体感一样。
2. 标定表清空后只开「前瞻」：没有「前瞻：」一行，也不起作用。

### 10.2 前瞻

1. 标定表填好，打开「伸缩跟随动作频率」→「前瞻（实验）」（+「相位脉动」）。播 `const-1hz`：状态行先「正在提前读后面的画面…」→「正在和实时画面核对」→ 3~6 秒内「频率和相位都按将来的画面」。
2. 第 8.2 节的延迟补偿在开着前瞻时要不要重调：用同样的 240 fps 拍法比一次，记下最佳延迟（前瞻会把「按现在的频率外推」换成画面实际走的相位，最佳值可能略变）。
3. 跳频 / 变速的视频：和不开比，伸缩快慢、脉动强弱是不是更早跟上画面。
4. 1080p60 HEVC、4K30 HEVC 各播 2 分钟：画面是否流畅、手机温度；状态行有没有「解码跟不上播放」。

### 10.3 预扫描

1. 打开「自动适应画面」→「预扫描整段视频（实验）」，选视频后先别播：记「已扫 xx%」到扫完用了多久（视频长度 / 机型）。
2. 扫完再播：开头几秒强度是不是更贴这个视频；热身照旧，开头 3 秒仍从 0 升起。注意预扫描不保证开头更弱：安静的片子起点按全片范围，
   主体放大一开始就可能到 1.25 倍，热身过后可能比不开时略强（激烈的片子则不会开头太弱）——记下安静片子开头是否过猛。
3. 扫到一半关掉开关：进度行消失。扫到一半切到后台再回来：接着扫。扫到一半就开始播放：提示「已经开始播放，这次按实时学（不再扫描，换视频后重新扫）」，
   预扫描不再解码（结果这次已经用不上）；切到跟随声音再切回画面、已经扫完的不会从头重扫。

## 11. 声画融合（av-fusion F0 / F1）的真机验证

F0 只加观测（跟着「调试记录」开关），不改任何输出；F1 的「声画融合（实验）」默认关、只显示一行状态，也不改输出。完整设计见
`docs/visual-sync-design.md`「av-fusion F0/F1」。测试视频用 `bash Tools/make-rhythm-test-videos.sh` 生成（`av-` 开头的 6 个）。

### 11.1 关着时什么都不变（1 分钟）

1. 「调试记录」关着：和 v1.8.3 一样（Instruments 里音频线程 CPU 不变）。
2. 「跟随声音」：界面、强度和 v1.8.3 一样（融合不是第三种来源，来源选择没有新选项）。

### 11.2 声画偏移（F0 基线）

1. 240 fps 慢动作同时拍手机屏幕并收声，播 `av-flash-click-1.6hz`：数「闪白那一帧」到「咔哒波形起点」差几帧（× 4.17 ms），记 10 次的中位数 = 手机本身的声画偏移。
   有耳机 / 蓝牙音箱时各量一次（蓝牙会多 100~250 ms）。
2. 「跟随画面」+ 打开「撞击声相位校正」+「调试记录」，播同一个视频 30 秒后导出表格：
   - `av_tap_lead_ms`：tap 比出声早多少（稳定后的值，记下来；应在几十毫秒、不随时间漂）；
   - `av_tap_invalid` 应一直是 0（拿不到时间范围的回调数）；不是 0 记下片源格式；
   - `av_onsets` 相邻两次差 ≈ 0.625 秒（1.6 Hz），和 `video_t` 对得上。
3. `av-offset+120ms-1.6hz` / `av-offset-200ms-1.6hz` 同样导出：`av_onsets` 应比基线整体晚 0.12 秒 / 早 0.2 秒（量的是片源本身的偏移，不是手机的）。
4. 暂停 / 拖进度条 / 2× 倍速各做一次：`av_tap_lead_ms` 跳转后几拍内回到原值；2× 时 `av_play_rate` = 2.000。

### 11.3 声画耦合度（F1，「声画融合（实验）」）

前提：「跟随画面」+「伸缩跟随动作频率」+「相位脉动」都开（耦合要画面相位锁锁着），再打开「声画融合（实验）」，状态区出现「声画：」一行。

1. 开关前后各播同一个视频 30 秒：强度条、设备动作和关着时一样（F1 只显示）。
2. `av-flash-click-1.6hz`：4~6 秒内变「声画：耦合（C …）」并保持；`av-offset+120ms-1.6hz` 也应耦合（只是相位偏）；`av-offset-200ms-1.6hz` 记实际表现
   （F1 的集中度只看撞击落在画面相位上是否集中、不看偏多少，多半也耦合；F2 起才用偏移量）。
3. `av-music-only-120bpm`（画面静止）：「像配乐」，不出现「耦合」；`av-music-1.6hz-picture-1.6hz`（同频配乐、15 秒切镜）：切镜前可能短暂「耦合」，
   切镜后「切镜了…」约 2 秒，之后「像配乐」。
4. `av-voice-like-1.6hz`：「像人声」，不耦合。拿掉音轨的视频：「没声音」。
5. 真实片子撞击 / 配乐 / 说话各 10 段，打开「调试记录」导出，按 `av_state` / `av_c` / `av_p_music` / `av_p_voice` 记判断（误判的段落记下 `video_t`）；
   拍打声被判成配乐（有节奏的背景声）是已知风险，系数在这些表格上调。
6. 同时打开「撞击声相位校正」：校正的状态行和关着融合时一样（频带块共用不改它的输入）；中途开关融合 / 校正、拖进度条都不卡、不报错。
7. Instruments：Audio 线程每次回调耗时（融合开 / 关对比，应只多几十微秒）、主线程每拍融合耗时、整体 CPU（应 ≤ 1% 单核）。

## 12. 节奏由声音确认（av-fusion F2）的真机验证

「节奏由声音确认（实验）」默认关，要「跟随画面」+「声画融合（实验）」+「伸缩跟随动作频率」都开才显示；判断耦合还要「相位脉动」。
打开后状态区多一行「节奏确认：…」，调试表格多 5 列 `av_vote` … `av_fast_jump`。完整设计见 `docs/visual-sync-design.md`「av-fusion F2」。
这一节的结果也决定 F3b 做不做。

### 12.1 关着时什么都不变（1 分钟）

1. 开着「声画融合」、关着「节奏确认」：同一个视频 30 秒，强度条 / 设备动作 / 撞击声校正的状态行和 v1.8.4 一样（没有「节奏确认：」一行）。
2. 关掉「伸缩跟随动作频率」：「节奏确认」开关消失、不起作用。
3. 暂停 / 停止 / 拿掉画面轨的视频 / 跟随声音时：Instruments 里音频线程每次回调耗时回到融合关着的水平（F1 复审 L2：这时不算 6 段特征）；
   再点播放，「声画：」一行几秒内回来。

### 12.2 容易读错八度的片子（快速往复、15 fps 量化）

1. 先关着「节奏确认」播一段快速往复（约 2 Hz、有清楚的撞击声）的真实片子，调试表格里 `subject_follow_hz` / `rhythm_hz` 在 1 Hz 和 2 Hz 之间来回跳的段落记下 `video_t`。
2. 打开「节奏确认」重播同一段：「声画：耦合」之后，这些段落 `av_vote = octave_up / octave_down`、`rhythm_hz` 应一直在真实频率附近，
   伸缩档位不再忽快忽慢；记「读错八度的拍数」开 / 关对比。
3. 一下两响的片子（往里、往外各有一声）：`av_vote_clean` 应多为 0，不应出现把 1 Hz 改成 2 Hz 的 `octave_up`；出现了记下片段（这是已知风险）。
4. 画面从头就读错八度（一直是一半）的片子：F2 不纠正（进不了耦合，`av_state` 多半是 `uncoupled`「频率对不上」），这是设计如此，记下有多少。

### 12.3 跳频 / 一致

1. `step-1to2hz`（或真实片子里节奏突然变快的段落）：开 / 关「节奏确认」各播一次，记跟随频率跟上的时刻（`rhythm_hz` 第一次接近新频率的 `video_t`）；
   有撞击声且耦合时 `av_fast_jump = 1` 那一拍就跳，应早约 0.3 秒；没声音的测试视频两者一样（不耦合 = 只看画面）。
2. `av-flash-click-1.6hz`：耦合后 `av_vote = agree`，「节奏确认：声音 1.60 次/秒和画面一致」；跟随器锁定不会比关着时晚。

### 12.4 配乐 / 舞蹈：撞击声校正不再被配乐带偏

1. 同时开「撞击声相位校正」。`av-music-1.6hz-picture-1.6hz`（同频配乐、15 秒切镜）：关着「节奏确认」时撞击声校正可能「已对齐」；
   打开后切镜考验认出配乐，状态行变「撞击声校正：声画不耦合（像配乐 / 人声）…」，偏移 2 秒后慢慢回 0，脉动按画面相位。
2. 舞蹈 / 有背景音乐的真实片子各 5 段：开 / 关「节奏确认」对比，脉动时机是不是不再跟着音乐漂（主观 + `av_state` / 校正状态行记录）。
3. 画面静止 + 音乐（`av-music-only-120bpm`）：任何时候设备都不能因为声音动起来（`rhythm_locked` 一直 0）。

## 13. 声音重音 / 震动跟声音（av-fusion F3）的真机验证

「声音重音（实验）」默认关，「声画融合」开着才显示；「震动跟声音（实验）」在重音开着、通道 = 两个都用时才显示。调试表格多 3 列 `av_accent_g` / `av_vib_mix` / `av_vib_level`。

### 13.1 关着时什么都不变

1. 融合开、重音关：同一视频 30 秒，设备动作 / 强度条和 F2 一样，三列为空。
2. 重音开但「声画：不耦合」（配乐 / 人声 / 画面静止 + 音乐）：`av_accent_g` 一直 1.000、`av_vib_mix` 一直 0.00；画面静止时设备不动。

### 13.2 重音

1. `av-flash-click-1.6hz` 或有清楚撞击声、轻重不一的真实片子：耦合后重的那几下 `av_accent_g` 接近 1 + 深度、轻的接近 1 − 深度；主观是否「重的一下更有力」。
2. 深度 0 / 15 / 30 各播一次，记主观感受和最大档位；任何时候不超过上限、升幅不突兀。
3. 开 / 关「相位脉动」各一次：脉动开着时变化在脉动深度上，关着时在强度上。

### 13.3 震动跟声音

1. 通道 = 两个都用，打开子开关：耦合时 `av_vib_mix` 0.6 秒爬到 1，震动随撞击轻重变化，伸缩不受影响；`av_vib_level` ≤ 画面震动 × (1 + 深度)。
2. 切到配乐段 / 画面停住：1.5 秒内 `av_vib_mix` 回 0、震动回到画面值，没有突然掉档。
3. 通道改成只用一个：开关消失、不起作用。

```
F3b 震动：耦合时跟得上 ___/5；淡回突兀 ___ 次；伸缩被影响 ___ 次
```

## 14. 画面不可用时按声音补（av-fusion F4）的真机验证

「画面不可用时按声音补（实验）」默认关，「声画融合」开着才显示。调试表格多 3 列 `av_fallback_share` / `av_video_gone_s` / `av_flywheel`。

1. 关着：发热 / 遮挡时行为和 F3 一样（设备归 0）。

## 15. 音画偏移（av-fusion F5）的真机验证

「音画偏移」滑杆和「自动估计音画偏移（实验）」在「声画融合」开着时显示，默认 0 / 关。

1. 滑杆 0、自动关：和 F4 完全一样（`av_offset_ms = 0`）。
2. 做两个变体：同一段拍打片子把音轨整体挪 +120 ms、−200 ms（ffmpeg `-itsoffset`）。手动把滑杆调到对应值时，「声画：耦合」应比 0 时更快、更稳；调反了应更差。
3. 打开自动估计，播一段快慢有变化（至少 0.4 次/秒的差别）的片子：状态行出现「自动估计 +___ 毫秒」，和真实偏移差多少记下；快慢不变的片子应一直「变化还不够」。

```
F5 偏移：+120 变体估成 ___ ms / −200 变体估成 ___ ms；估不出的片子 ___/5；手动调对后耦合更快 ___/5
```
